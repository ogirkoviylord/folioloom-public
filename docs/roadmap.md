# Product roadmap

FolioLoom is pre-MVP and actively developed. This is a product direction, not a release calendar. No delivery dates are announced; scope and order may change as we learn. The web Workbench is not publicly available yet.

## Current focus: the connected DOCX workflow

Bring a document in, explain author intent, agree terminology, generate a translation draft, review it and export a usable document. DOCX is the current development focus. Existing TXT and EPUB processing foundations remain part of the project, not evidence of a finished multi-format Workbench.

Representative evaluation and author feedback should establish whether the connected process helps with meaning, terminology and document structure. Improved quality, time savings and publication-ready output have not been demonstrated.

## From preserving a book to designing an edition

### Preserve the book

Preserve reading order, chapters, headings, emphasis, images, tables, links and notes within each format's supported limits. This is an existing aim, not proof of complete visual fidelity. Translated text can change length, so identical pagination is not guaranteed.

### Refine the translated edition

Develop an editing workflow for revising translated text and adjusting chapter structure, styles, images and notes before export. This is a future direction, separate from existing review foundations and the read-only Reading Mode design.

### Book design and typesetting

The long-term aim is a full book-layout workspace: page size, margins, typography, running headers and footers, page numbering, contents and preview before export. The layout engine, supported export subset and implementation sequence are not decided. This is not an available publishing editor, a promise of parity with every editor or a guarantee of printer/publisher acceptance.

## Broader format support

Beyond existing TXT/DOCX/EPUB foundations, the direction includes:

- Books and documents: **FB2, RTF, ODT, legacy DOC, HTML/HTM and Markdown**.
- Structured text and Kindle formats: **selected text columns in CSV/TSV, MOBI, AZW3 and KPF**.
- Further investigation: **PDF**, including scans requiring OCR; image-heavy **CBZ, CBR and DjVu**; and **batches of supported documents in ZIP archives**.

This is not an accepted-upload list or a fixed delivery order. Each format needs its own preservation, parser-safety, fixture and output-validation work. OCR, image-heavy content and batch processing require separate investigation. Subtitle translation is not part of this roadmap.

## Separate longer-term idea

Game/modpack localization is a distinct future hypothesis: translate supported human-facing strings while preserving identifiers, placeholders and technical structure. It is not part of the current book workflow and does not imply support for arbitrary modpack archives.

## What guides the order

Author/rightsholder needs, representative authorised documents, preservation of content, usable output and manageable complexity should guide which capability comes next. Qualified bilingual judgment remains important when checking accuracy in an unfamiliar language.

Broader access depends on workflow, quality and reliability evidence. There are no announced alpha, beta or public-launch dates.
